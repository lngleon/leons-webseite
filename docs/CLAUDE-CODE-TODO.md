- [x] **WCAG 2.5.3 am Logo geschlossen – und die Fehlerklasse einmal über die ganze Seite gezogen, Demos eingeschlossen** (28.08.2026).
  **Der Fund:** der Logo-Link zeigte sichtbar „LL", sein `aria-label` lautete „Leon Lang – Startseite". Das ist kein fehlender Name, sondern ein **ersetzter**: Screenreader lasen korrekt vor, aber Sprachsteuerung fand den Link nicht – „Klick LL" traf ins Leere, weil „LL" im zugänglichen Namen gar nicht vorkam. Genau das verbietet WCAG 2.5.3 („Label in Name"). **Neu:** `aria-label={`${logoText} – Startseite von ${name}`}` → **„LL – Startseite von Leon Lang"**, im a11y-Baum des Browsers gegengeprüft. Das Kürzel steht vorn, der Rest erklärt es; kein Logo-Redesign, ein Attribut.
  **Der Durchgang über alles:** ein Skript im echten Browser vergleicht für **jedes** Bedienelement (`a[href]`, `button`, `input`, `select`, `textarea`, `summary`, `role=button|link|tab|checkbox|radio`) den **sichtbaren Text** gegen den **zugänglichen Namen** – `aria-labelledby` vor `aria-label` vor Textinhalt, `aria-hidden`, `display:none` und `sr-only` herausgerechnet, `img`-`alt` **nicht** als sichtbarer Text gewertet (2.5.3 meint gerenderte Schrift).
